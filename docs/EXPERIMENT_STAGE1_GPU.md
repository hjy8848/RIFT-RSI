# 阶段 1 第一次真实训练（GPU）：设计与判据

## 问的问题
用 Designer 出的题（加一部分生成器的题）训练客服模型 Qwen3-4B 之后，**在同一批没见过的留出题上，成绩比训练前高吗？**

## 设计
| 项 | 取值 |
| --- | --- |
| 模型 | Qwen3-4B，GRPO（VERL 0.9.1，FSDP2 + vLLM），学习率 1e-6 |
| 训练池 | Designer 的题 54 道（两批阶段 0 合并、按判断签名去重、不含"送达天数指代"）；每轮 25% 取自生成器的均衡题（69 道，同样不含送达天数指代） |
| 每轮 | 8 道题 × 每题 4 次采样 = 32 个对话，mini-batch 8，15 轮 |
| 留出集 | `configs/experiments/designer_heldout.json`，96 道生成器的题；训练前的成绩已在同一批题上测过（`rift-base-eval-1gpu-20261104a`，每题 8 次） |
| 训练后评测 | 训练结束后在原地评测同一批 96 道题，每题 8 次（`--heldout-groups 2`，评测种子 2000，与基线一致） |
| 平台 | CUDA，2 或 4 张空闲 GPU（`scripts/stage1_gpu.sh` 等卡、加锁、只对早期失败重试），`NCCL_P2P_DISABLE=1` |
| 耐心 | 不开（基线也没开） |

排除"送达天数指代"的题，是因为 Service 看不到今天的日期，这类题无法识别（见 `RESULTS_BASELINE_20261104.md` 第 5 节）。留出集不重新生成：对比时**只看训练前后都有、且不含送达天数指代的那 68 道题**，按题配对。

## 怎样算有结果
- **主指标**：这 68 道题上训练后与训练前的成功率之差，按题配对，对题做自助重抽样给 95% 区间。
- **保持类**：训练前就高于 90% 的类（F1、F2、F3、F4、F8）不能掉。
- **分类看**：F6、F7、F9 这些训练前低的类有没有涨。
- 区间含 0 就是"没有证据"，不说"有效"也不说"无效"。
- 只有一次运行、一个种子：结论只能是"这次运行里看到了/没看到"，不是"这个方法有效"。

## 已知的局限
- 题池小（54 + 69），15 轮每题最多被看到几次，容易过拟合训练题；留出集是不同的题所以能暴露这一点。
- Designer 是没训练过的原模型，失败材料是一次性的快照（见对话记录）；这不是完整的 RIFT 闭环，只验证"Designer 的题能不能训练出提升"。
- 没有对照组（用同样预算训练纯生成器的题）。如果有提升，不能说明提升来自 Designer 的题而不是来自"训练"本身；需要的话后面再加。
