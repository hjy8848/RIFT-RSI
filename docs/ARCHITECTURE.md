Scope: first-stage execution boundaries and remaining adapters

This design defines the trusted Host boundary and the stopping condition for the first implementation; see [research spec](RESEARCH_SPEC.md) and `src/rift/` for the source of truth.

Native Usami records, task objects, certificates, replay and outcome evaluation belong in the Host. `benchmark/usami.py` lazily calls the pinned native commerce APIs; `private_evaluation.py` projects allowlisted event fields and a business-only outcome. Certification reports bounded task reachability, not natural interaction solvability. A proposal and a certificate are separate objects. No raw certificate or native record is a model input. `ReplayBank` accepts replay-partition real-model successes and freezes a content-hashed snapshot only against disjoint train identities; it does not infer optimal actions. SplitRegistry rejects registered cross-split identity overlap; correct identities and lineage must still come from a trusted upstream source. Grounding and compilation call the native Usami structured challenge APIs inside the Host; the native compiler renders its request rather than trusting a free-form proposal request. The event projection is an observation summary, not a reconstruction of exact model prompts or token IDs. Capturing and validating exact model inputs, action tokens, and model interface is still required before training or genuine replay scoring.

`training/service_data.py` constructs a request only from native replay-verified episodes and a trusted future token recorder. Designer credit belongs to the entire package action, not to an individually proven task. Comparable credit requires the same full Service baseline, snapshot and normalization. `training/contracts.py` declares Service and Designer backends, checkpoint store and token-level scorer; `replay/reward.py` computes masked before/after scores for an externally supplied completed update. The supplied evidence fields are references, not cryptographic attestation. A real backend and checkpoint store must validate them. No trainer or scorer implementation is supplied. `loop.py` persists requests, externally reported completed updates, replay results and Designer requests with binding checks; it invokes no trainer, scorer or model. Backend and storage implementations must authenticate update evidence before real use.
