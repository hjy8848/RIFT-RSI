This document tracks which components block a reproducible RIFT experiment; the contracts are in `src/rift/` and the research decision in [RESEARCH_SPEC.md](RESEARCH_SPEC.md).

Implemented: proposal/certificate separation, host-only native API wrappers, public event and outcome projection, replay snapshot and overlap checks, token-masked reward arithmetic, trainer/scorer/checkpoint protocols, and training-request/state persistence. `orchestrator.prepare_round` composes injected Designer and benchmark actors up to the training boundary. These are scaffolding; a caller must preserve Host isolation and trusted provenance. The native certificate proves bounded business reachability and does not certify natural customer interactions.

The default commerce Customer scenario and profile support structured remedy-only tasks with a shared conservative policy; information goals, return scheduling, and review events need explicit implementations. Certification proves bounded business reachability, not natural dialogue success.

The `rift.verl` package contains a v0.9.1 Agent Loop extension, a stepwise bridge to the native Usami runner, continuous-token capture, a Designer sampler, whole-episode Service data preparation, and host-side generation and update ledgers. Service group verification checks same task and initial prompt, distinct rollout seeds, and complete predeclared group size; UNKNOWN drops the entire group. Both roles have a VERL actor-worker backend: Service GRPO and Designer GRPO when complete comparable groups exist, otherwise Designer REINFORCE++ with gamma 1. One `update_actor` call may optimize across several minibatches and epochs but advances VERL's outer global step by one. The backend saves the full FSDP2 checkpoint at that exact step, synchronizes through the official `CheckpointEngineManager`, then requires every vLLM response to report matching `global_steps` bounds. This is step evidence, not a hash attestation of tensors resident in a server. CPU tests use a scripted parser, fake model server, fake actor worker, and dummy checkpoint shards; no real generation or optimizer step has been verified.

The `rift-verl-round` entry point resumes or executes one persisted round through a caller-supplied `VerlRoundRuntime` factory. That factory must construct the certified-task resolver/authorizer, Customer factory, capture stores, checkpoint sources, replay snapshot resolver, runtime verifier, and actual worker groups. The repository does not yet provide a production Ray/FSDP2 worker launcher or an NPU resource handoff implementation. `NativeHostProvider` consumes opaque task references, but an authoritative persisted task registry and dataset adapter must be supplied by the caller. `RecomputedReplayRewardVerifier` re-scores a supplied snapshot but relies on trusted update, checkpoint and demonstration verifiers. The strict continuous-prefix check may reject a valid model/template boundary rewrite and must be checked against the actual tokenizer/template. No real Ascend or target dependency-stack validation has been run.

Also not yet implemented: independent evaluation, cross-checkpoint normalization, an explicitly versioned same-family split ablation, and production trust roots for worker/task/update evidence. Mock evidence and dummy checkpoint files establish no real model update or replay measurement. The specified NumPy version conflicts with upstream v0.9.1's dependency requirement; see [VERL_INTEGRATION_DESIGN.md](VERL_INTEGRATION_DESIGN.md). No model learning or performance result is claimed. The current implementation is an offline-tested integration adapter and must not be presented as a verified Ascend training run.
